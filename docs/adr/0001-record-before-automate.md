# ADR 0001: Спершу запис, потім автоматизація

- Статус: прийнято
- Дата: 2026-09-30

## Контекст

Автоматизація спирається на розбір відповідей @toadbot. Що відомо на старті:
- точних текстів більшості відповідей ми не знаємо (є лише кілька скрінів);
- бот відповідає звичайним повідомленням, а не реплаєм, і не згадує власника;
- бот видаляє команди й відповіді приблизно через 5 хв, тож пізніше перечитати їх неможливо (а перечитувати чат ще й небезпечно, див. ADR 0002).

## Рішення

Етап 0 — пасивний **Recorder**. Юзербот нічого не надсилає в чат. Він записує в SQLite кожне повідомлення бота в робочому чаті та кожну команду, адресовану боту, одразу при отриманні: текст, entities (зокрема кастомні емодзі), кнопки, редагування і видалення. Власник тим часом грає руками кілька днів.

## Наслідки

- Парсери й тести наступних етапів будуються на реальних даних (`.export` → фікстури), а не на здогадах.
- З'являються дані для кореляції без реплаїв: порядок і інтервали між командами (своїми й чужими) та відповідями.
- Контрол-команди, логування, Docker і CI вводяться вже на етапі 0 і далі лише розширюються.
